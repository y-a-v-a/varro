The inventory

Six files, of which two are the model

Training wrote six files. Only the first two are needed to use the model — the rest let you resume an interrupted run, or establish where the model came from. If you copied just those two onto another machine, it would work.

FileSizeWhat it holdsNeeded to run?
latin-xxv-2.safetensors 104.9 MB The 27,493,376 learned numbers. This is the model. Essential
latin-bpe-4000.json 250 KB The 4,000 word-pieces the numbers are indexed by. Essential
latin-xxv-2.opt.safetensors 209.8 MB The optimiser's working notes — twice the size of the model, and discardable. Resume only
latin-xxv-2.state.json 2 KB Which step training reached, and the loss at each checkpoint. Resume only
train-latin-xxv-2.json 4 KB What it was trained on, through which vocabulary, and how it scored. Provenance
latin-xxv.yaml 2 KB The recipe — enough to train it again from scratch. Provenance
The optimiser file is twice the size of the model itself, which surprises people. While training, the optimiser keeps two running averages for every single weight — so three numbers are in flight for each one that survives. When training ends, its notes are finished with.
Opening the first file

The weights are 84 tables of numbers

Inside latin-xxv-2.safetensors there is no code and no text — just named grids of decimals. Here are four of the eighty-four, at their real sizes: 

embed.weight                      (4000, 512)   float32
pos.weight                        ( 512, 512)   float32
blocks.6.fc1.weight               (2048, 512)   float32
blocks.6.attn.value_proj.weight   ( 512, 512)   float32

embed.weight is the one worth understanding first. It has one row per word-piece — 4,000 rows — and each row is 512 numbers long. That row is what the model knows about that piece. Row 2247 belongs to the piece Gall, and begins: 

-0.0133  -0.0136  -0.0814  -0.0976  -0.0505  0.0753  0.0684  0.0084  …

No single number in that row means anything on its own. Nothing in the file says “Gaul” or “noun” or “place”. The meaning is entirely in how the 512 numbers sit relative to every other row — which is why you cannot open a model and read it, and why the only way to find out what it learned is to run it and look at what comes out.

The remaining eighty-odd tables are the layers that transform those rows in context — eight repeating blocks, each with an attention part that lets a word look at the words around it, and a larger part that does the actual reshaping. blocks.6.fc1.weight is one of the latter, in the seventh of the eight blocks.

Opening the second file

The vocabulary is a list of 4,000 pieces

The model cannot read letters. Before any Latin reaches it, the text is cut into pieces from a fixed list, and each piece is replaced by its position in that list. Watching one word go through is the clearest way to see it:

Latin
amabamus  — “we were loving”
Cut into pieces
am · ab · amus
Looked up
527 · 344 · 739
What the model sees
three rows of 512 numbers

Notice the split: am is the stem, ab marks the imperfect tense, amus marks “we”. The vocabulary is small on purpose — at 4,000 pieces the model is forced to learn Latin's endings, because it cannot afford to store every inflected form whole. A 64,000-piece vocabulary stores amabamus as a single entry and learns nothing from it.

Six entries in the list are not Latin at all. <|endoftext|> marks where one document ends, and four era markers — <CLASSICAL>, <LATE>, <MEDIEVAL>, <NEOLATIN> — were placed in front of each document during training, so the model can be asked for one period rather than another.

Why both

The small file is not the optional one

weights
104.9 MB

250 KB · 0.24%

The vocabulary is a quarter of one per cent of the model's size, and the model is worthless without it. The weights are indexed by position in that list: row 2247 means Gall only because the list says entry 2247 is Gall. Hand the model a different list and every row points at the wrong thing.

This is not hypothetical. On 20 August a corpus rebuild retrained the vocabulary in place, and the previous model's list was overwritten. Its weights were untouched and completely unusable — and it would not have failed, it would have produced fluent, confident, meaningless Latin. The file was recovered by rebuilding the corpus that produced it and retraining the vocabulary, which came back byte for byte identical. Vocabularies are now archived by content and never overwritten.
What it is not

Three things that are not in the folder

The corpus is not in there. The model learned from 506.7 MB of Latin and is 104.9 MB — a fifth of the size, and not a compressed copy. Of 1,297 twelve-word passages it generated, none appears anywhere in its training text. It absorbed how Latin behaves, not the sentences it read.

There is no knowledge in there. It writes grammatical Latin about nothing. Asked for classical prose it produced a sentence placing the town of Munda near the Nile — Munda is in Spain. All surviving Latin, across fifteen centuries, is roughly two years of one committed reader's intake; that is enough to learn a language and nowhere near enough to learn the world.

There is no program in there. The file holds only numbers. Something has to load them, feed them text, and read off the answer — that is what src/sample.py and src/score.py do. The same weights run under any code that knows their shape.

Using it

Two things it can do today

Write Latin

python src/sample.py --name latin-xxv-2 --n 5 --period CLASSICAL

Give it a starting point and it continues. Conditioned on <CLASSICAL> it writes like a Roman historian; on <MEDIEVAL>, like a monastic chronicler.

Judge Latin

python src/score.py --name latin-xxv-2 FILE
python src/score.py --name latin-xxv-2 --period-fit FILE

Run backwards, the model reports how surprising a piece of text is. That number sorts real Latin from damaged Latin from text that is not Latin at all — and scoring the same passage under each era marker suggests which century it belongs to.

Both routes check the vocabulary's fingerprint against the one recorded when the model was trained, and refuse to run on a mismatch rather than quietly producing nonsense.
Provenance

What the model can prove about itself

The two small bookkeeping files are what separate a model you can publish from a file of numbers somebody hands you. Between them they record:

  • the exact corpus build it saw — 10,177 documents, 78,554,197 words, every source licensed and named;
  • the fingerprint of the vocabulary it was trained through;
  • the recipe that produced it, stated in passes over the corpus rather than step counts, so re-running it on a larger corpus still means the same thing;
  • its score — 30.1, against 149.5 for a deliberately simple method given the same text.

That last comparison is only meaningful because both numbers were measured on the same text through the same vocabulary. LATIN-XXV-2 is the first model in this project able to demonstrate that, which is why it is the only one whose score is quoted without a warning beside it.
